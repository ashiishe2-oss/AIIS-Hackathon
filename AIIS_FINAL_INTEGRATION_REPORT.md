## 4. End-to-End Workflow Verification

### Workflow A: Citizen Emergency SOS
1. **Unauthenticated Access:** Citizens access emergency search without mandatory login.
2. **Facility Discovery:** `POST /api/emergency/search` delivers facilities with `partner: True`, distance calculations, and real-time bed availability.
3. **Emergency Dispatch:** `POST /api/coordination/request` dispatches the SOS request, decrements available bed hold, and returns:
   - `request_id` (UUID format)
   - `tracking_token` (64-character hex token)
   - `arrival_otp` / `otp` (4-digit numeric code for desk presentation)
4. **Status Polling & Security Redaction:** Status updates polled via `GET /api/coordination/<id>` with `X-Tracking-Token` strictly redact the OTP from the response payload to prevent intercept attacks.
5. **Guest Protection:** Unauthenticated or guest attempts to call `verify-arrival` using only a tracking token are rejected with `403 Forbidden`.

### Workflow B: Hospital Coordination & Intake Desk
1. **Staff Authorization:** Hospital staff access the desk using standard JWT credentials or the emergency fallback code (`X-AIIS-Staff-Code: DEMO2026`).
2. **Live Casualty Intake Queue:** The desk queries `GET /api/hospital/<id>/requests`, displaying incoming emergency arrivals with countdown timers, acuity tags, and patient details.
3. **1-Tap OTP Verification:** Hospital desk staff verify patient arrival via modal entry or 1-tap verification (`POST /api/coordination/<id>/verify-arrival`). The request transitions to `PATIENT_ARRIVED`, releasing hold state and confirming admission.
4. **Capacity Management:** Hospital administrators update bed availability via `POST /api/hospitals/<id>/capacity`. The provenance is recorded as `hospital_admin_reported` with `verified_realtime: False` (reserving `verified_realtime: True` strictly for hardware telemetry).

### Workflow C: Regional Health Authority Dashboard
1. **Regional SRI Surveillance:** `GET /api/sri/regional` aggregates live stress scores across all monitored facilities in Karnataka/Bengaluru.
2. **Zone & District Aggregation:** Results provide hierarchical breakdown:
   - Composite Regional Score (e.g., SRI 38 / Moderate)
   - District Strain Index (Bengaluru Central, Urban, South)
   - Facility Level breakdown for all 36 healthcare institutions.
3. **Visual Risk Categorization:** All zones and facilities report standardized risk levels (`LOW`, `MODERATE`, `HIGH`, `CRITICAL`).

### Workflow D: Planned Care & Outpatient Appointments
1. **Specialty Search:** `POST /api/planned/search` filters hospitals by medical specialty (Cardiology, Neurology, General Medicine, Pediatrics, Orthopedics).
2. **Appointment Request:** Citizens book appointments via `POST /api/appointments/request`, accepting flexible input keys (`hospitalId` / `hospital_id`, `patientPhone` / `patient_phone`).
3. **Authenticated Management:** Historical visits are retrieved via `GET /api/appointments/me` and `GET /api/appointments?phone=...`, strictly scoped to the authenticated caller.
4. **Cancellation Security:** Appointments can be cancelled via `POST /api/appointments/<id>/cancel` by authorized users, correctly returning `401 Unauthorized` for unauthenticated requests and `403 Forbidden` for cross-patient attempts.
